# Assignment 11 — User Interface

A Gradio user interface for the team's chat-based multimodal RAG system. It is the interaction
layer on top of the earlier project components and follows the Figma design in
`../Interface_Mockup/`: a dark, three-column layout.

```
  CHAT                    TOP-K RETRIEVAL              SYSTEM INSPECTION
  chat window +           Articles | Videos tabs       system prompt, token budget,
  text input + send       ranked results + player      injected context, settings, latency
```

## Files in this folder

| File | What it does |
|------|--------------|
| `app.py` | The Gradio UI — layout, styling and all interactions (Tasks 1–3). |
| `rag_backend.py` | Connects the UI to the pipeline. It does **not** re-implement anything: its `load_notebook` imports the notebooks' own `ArticleRetriever` / `VideoRetriever` / `build_prompt` / `generate_reply` (skipping their demo cells), loads the frozen models, and exposes one `answer(history, query)` call. Falls back to a small offline mock if the data/models are absent. |
| `requirements.txt` | Dependencies (only `gradio` beyond the pipeline's stack). |

## How it connects to the rest of the project

This assignment adds only the UI; the pipeline lives in the sibling notebooks and is **called**,
not copied:

```
../01_Preprocessing.ipynb   ─┐  ../build_data.py runs these to produce (once)
../02_Chatbot_Setup.ipynb    ├─ ../wikihow.db + ../Data/Embeddings/*.faiss + ../Data/HowTo100M/*
../03_RAG.ipynb             ─┘
rag_backend.py               load_notebook() imports the notebooks' code (no rewriting), then
                             instantiates 03's retrievers + calls 03's build_prompt/generate_reply
```

> The built data (`wikihow.db`, FAISS indices, clips) is **not** committed — it is regenerated by
> `../build_data.py`. That script is only needed once to build the data; running the UI itself
> does not need it.

## Running

**If the data already exists** — e.g. a teammate has run `../01_Preprocessing.ipynb` and the
project folder contains `wikihow.db` + `Data/` — just install and launch:

```bash
pip install -r requirements.txt
python app.py            # http://127.0.0.1:7860
```

`rag_backend.py` locates the artifacts automatically (absolute paths from the project folder,
independent of your working directory), and accepts the text indices whether `01` left them in
the project root or in `Data/Embeddings/`. The models (MiniLM ~90 MB, CLIP ~600 MB, TinyLlama
~2.2 GB) download from Hugging Face on first run.

**If the data does not exist yet**, build it once (this runs `01`'s preprocessing for you; see
`../README.md` for the dataset links):

```bash
cd .. && python build_data.py && cd 11_User_Interface && python app.py
```

If the artifacts/models are missing the UI starts in an offline mock so the interface is still
demonstrable (`AML_FORCE_MOCK=1 python app.py` forces it).

### What the UI needs at runtime
- `../02_Chatbot_Setup.ipynb` and `../03_RAG.ipynb` (their code is imported — **all three
  notebooks should be present**; `01` is only needed to build the data).
- `../wikihow.db`, `../Data/Embeddings/*.faiss`, `../Data/HowTo100M/clip_metadata.csv` and the
  clips under `../Data/HowTo100M/videos/` — produced by running `01` (or `build_data.py`).

## Assignment tasks

- **Task 1 — Chat interface & state management.** `gr.Chatbot` window, text input with Enter-key
  **and** a Send button. The conversation history lives in `gr.State` and is passed to the
  backend each turn; sending updates the history, clears the input, and refreshes the injected
  context and the token indicator.
- **Task 2 — System inspection & token transparency.** A read-only, auto-updated panel: the
  active system prompt, total token usage vs. the model's context budget (budget bar), the
  injected articles/clips with per-item token cost, retrieval settings and a latency breakdown.
- **Task 3 — Video panel & playlist.** A video player plus a ranked playlist of retrieved
  segments (from the backend). Clicking a segment loads its clip, seeks to the timestamp and
  autoplays. Video content is never placed in the LLM prompt.
- **Task 4 — Demonstration video.** Separate deliverable, uploaded to the repository root.

All models are used frozen (inference only). Built against `gradio==6.19.0`.
